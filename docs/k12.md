# k12 (Linux dev box)

k12 is an Ubuntu 26.04 machine on my Tailscale network. Coding agents (Claude
Code, Codex) run on it through T3 Code. It takes only the shell and agent
config from this repo; the rest of `stow/` is desktop config for the Mac.

## Packages

Login shell: zsh (`chsh -s /usr/bin/zsh`).

From the Ubuntu archive:

```
sudo apt install zsh zsh-syntax-highlighting stow jq git eza bat fzf \
  starship atuin zoxide neovim lazygit tmux
```

Ubuntu installs bat as `batcat`; `.zshrc` aliases `cat` to whichever exists.

Other system packages:

- Tailscale: from Tailscale's apt repo (`pkgs.tailscale.com`).
- mise: installed as a `.deb`, with no apt repo configured for it.

User installs, outside apt:

- Claude Code: native installer, `~/.local/bin/claude`.
- Codex: standalone installer, `~/.codex/packages/standalone`, linked from
  `~/.local/bin/codex`.
- opencode: `~/.opencode/bin`.

mise global tools come from k12's own `~/.config/mise/config.toml`, not the
repo's `mise` package: bun, carapace, java 17, just, node 24, overmind, pnpm 10.

## Linking

```
git clone https://github.com/ruigomeseu/dotfiles.git ~/code/dotfiles
~/code/dotfiles/scripts/link
```

On Linux, `scripts/link` stows `zsh`, `claude` and `codex`, moving any file in
the way to `~/.dotfiles-backup/<timestamp>/`, and sets
`CLAUDE_CODE_SHELL=/bin/bash` in `~/.claude/settings.json`.

## Machine-local environment

`~/.zshenv.local` (mode 600, never committed) holds what only k12 needs:

- `PORTLESS_TAILSCALE=1`, so Portless dev servers register on the tailnet.
- `CLAUDE_CODE_OAUTH_TOKEN`, a long-lived Claude Code OAuth token.

## Coding agents

- Claude Code runs its Bash tool in bash (`CLAUDE_CODE_SHELL`), so it never
  reads the zsh config.
- Codex has no shell setting. `~/.codex/AGENTS.md` asks it to run commands in
  bash; if it uses zsh anyway, `.zshenv` turns on `NO_NOMATCH` and
  `SH_WORD_SPLIT` for Codex shells.
- Bash agent shells inherit PATH from whatever launched the agent. T3 Code
  starts with the login environment, so mise tools resolve.
- Claude Code blanks `CLAUDE_CODE_OAUTH_TOKEN` in its tool shells. A `claude`
  started from inside a Claude session falls back to
  `~/.claude/.credentials.json` unless the token is passed explicitly.

## History

Until 2026-10-03, `~/.zshrc` was a copy of this repo's `.zshrc` from commit
`b4b9c9f`, with installer lines appended, and `~/.zshenv` held the token. Both
were replaced by stow links; the old files are in `~/.zsh-backup-20261003/`.
